## 1. Product Design Vision & Principles

The Digital Menu SaaS delivers a commercial-grade, multi-tenant digital menu browsing experience tailored for restaurants, bistros, and cafés. It prioritizes speed, legibility, and zero-friction customer access via printed QR codes.

### Core Principles
1. **Zero-Friction Dining Browsing:** Diners access menus instantly without creating accounts, downloading apps, or facing marketing popups.
2. **Display-Only Focus (MVP Scope):** Strictly display-only. Patrons browse categories, dishes, photos, descriptions, and prices (EGP). No cart, checkout, payments, ordering, delivery, or POS integrations in MVP.
3. **Arabic-First (RTL) Native Experience:** Native Arabic RTL is the default, accompanied by high-quality English (LTR) with seamless single-tap language switching.
4. **Performance & SEO First:** Public routes (`/r/:slug`) employ Angular Hybrid SSR to deliver complete, semantic HTML on first paint. Target Core Web Vitals: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1.
5. **Simplicity for Non-Technical Restaurant Owners:** Routine price updates and availability toggles ("نفد" / "In Stock") take seconds from any smartphone or tablet.

### Domain A: Public Customer Menu (`/r/:slug`, `/m/:publicCode`)
- Designed for mobile smartphones under real restaurant ambient lighting.
- Immediate SSR HTML render without requiring JavaScript execution.
- High visual contrast, clear food photography, and intuitive category navigation.

### Domain B: Restaurant Owner Dashboard (`/admin/*`)
- Secure CSR authenticated application backed by HttpOnly/Secure cookies.
- Server-derived tenant scope (no client-supplied `tenantId`).
- Core workflows: Price adjustments, dish availability toggles, bilingual category/item editing, logo/theme customization, and QR code export.

### Domain C: Platform Admin Portal (`/platform/*`)
- High-level tenant governance, atomic tenant and owner provisioning, suspension/reactivation controls, and audit log tracking.

## 3. User Journeys & End-to-End User Flows

### Flow 1: Customer QR Scan to Dish Selection
1. **Scan QR Code:** Customer scans printed table QR code pointing to `https://origin/m/:publicCode`.
2. **One-Hop Redirect:** Server resolves active tenant and responds with HTTP `302` to canonical `https://origin/r/:slug`.
3. **SSR HTML Render:** Initial response arrives in `< 800ms` containing restaurant `<h1>`, categories `<h2>`, item articles `<h3>`, and prices in raw source.
4. **Hydration & Enhancement:** Angular client bundle hydrates without layout jumps. Sticky category scroll-spy and instant client search activate.
5. **Browsing & Detail:** Customer taps category chip to smooth-scroll, types in search for instant filtering, or taps dish card to open product detail bottom sheet.
6. **Language Switch:** Customer taps `[AR | EN]` button. Document direction flips (`rtl` <-> `ltr`), text updates to English with Arabic fallback where needed, preserving current scroll context.

### Flow 2: Restaurant Owner Menu Management
1. **Login:** Owner signs in at `/login` with credentials. Session established via secure cookie.
2. **Dashboard Overview:** Displays published status banner, count of active categories/items, and quick-action buttons.
3. **Price & Availability Update:** Owner opens `/admin/items`, filters by category, taps "Sold Out" toggle to mark an item unavailable in real time, or edits price in EGP.
4. **Dish Creation:** Owner adds dish, inputs required Arabic name, optional English name, price, and uploads food photo (JPEG/PNG/WebP, max 2MB).
5. **Brand & QR Export:** Owner customizes primary accent color with automated WCAG contrast validation, then downloads permanent vector SVG or PNG QR code for table printing.

### Flow 3: Platform Admin Tenant Provisioning
1. **Authentication:** Root administrator signs in.
2. **Tenants Directory:** Views active and suspended restaurants.
3. **Atomic Provisioning:** Clicks "Provision Restaurant", submits Arabic name, English slug, and owner email.
4. **System Execution:** Generates unique `RestaurantId`, permanent `PublicCode`, assigns owner identity, and issues secure setup link.

## 6. Visual Design Direction & Design Tokens

The visual direction follows **"Warm Modern Epicurean"**—a refined, appetite-inducing, high-clarity SaaS aesthetic combining deep slate neutrals with customizable culinary accents.

### Design Tokens Specification
Tokens are formally codified in `frontend/design/tokens.json` and `frontend/design/tokens.css`.

- **Brand & Semantic Colors:**
  - Default Brand Primary: `#0F766E` (Deep Emerald Teal)
  - Primary Container: `#CCFBF1` | On Primary: `#FFFFFF`
  - Canvas Background: `#F8FAFC` | Surface Card: `#FFFFFF`
  - Text Primary: `#0F172A` (WCAG AAA 16.2:1 against canvas)
  - Text Secondary: `#475569` (WCAG AA 5.9:1)
  - Text Muted: `#64748B` (WCAG AA 4.6:1)
  - Success Badge: `#15803D` / Container `#DCFCE7`
  - Warning Badge: `#B45309` / Container `#FEF3C7`
  - Danger / Error: `#B91C1C` / Container `#FEE2E2`
  - Sold Out Status: Text `#64748B` / Container `#F1F5F9`
- **Dynamic Tenant Theming:**
  - Bound via CSS Custom Property `--tenant-primary`.
  - Automatic WCAG AA contrast ratio validation prevents illegible custom colors.
- **Typography Scale:**
  - Arabic Font Family: `'Tajawal', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`
  - Latin Font Family: `'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`
  - Type Scale: `xs` (12px), `sm` (14px), `base` (16px), `lg` (18px), `xl` (20px), `2xl` (24px), `3xl` (30px).
- **Spacing Scale (4px Base):**
  - `space-1` (4px), `space-2` (8px), `space-3` (12px), `space-4` (16px), `space-6` (24px), `space-8` (32px), `space-12` (48px).
- **Touch Target Ergonomics:**
  - Minimum touch target: `44px x 44px`. Critical mobile buttons target `48px`.

## 7. Component Inventory

Detailed component contracts are documented in `frontend/design/component-catalog.md`. Key components include:
1. `BrandHeader`: Displays logo, title, tagline, and language toggle. Renders semantic `<h1>`.
2. `CategoryChipsNav`: Horizontal swipeable tab bar with sticky scroll-spy and keyboard arrow navigation.
3. `ProductCard`: Responsive dish card with square `1:1` image thumbnail, title, description clamp, price in EGP, and availability badge.
4. `ProductDetailSheet`: Modal bottom-sheet with focus trapping, swipe-down gesture, full description, and allergen indicators.
5. `SearchBar`: Debounced instant search with clear button (`[ ✕ ]`) and `aria-live` region.
6. `AvailabilityBadge`: Clear status indicator ("متوفر" / "نفد").
7. `StatePlaceholder`: Informative, welcoming empty and error cards (empty menu, search not found, offline, 404).
8. `SkeletonLoader`: Shimmer card placeholder matching exact pixel dimensions for zero Cumulative Layout Shift (CLS = 0).
9. `AdminDataTable`: Desktop data table that collapses to mobile card stack.
10. `ImageUploadZone`: Drag-and-drop food image uploader with client validation (WebP/JPEG/PNG, ≤ 2MB).
11. `QRAssetCard`: Vector SVG preview and one-click PNG/SVG asset download.

## 9. RTL (Arabic) & LTR (English) Specification

1. **CSS Logical Properties:** All layouts strictly use `margin-inline`, `padding-inline`, `inset-inline`, and `text-align: start`.
2. **Directional Iconography:**
   - Back and forward navigation arrows flip in RTL (`←` <-> `→`).
   - Search icon aligns to the inline-start position.
   - Prices align to the inline-end position.
   - Phone numbers and currency ISO symbols maintain invariant orientation.
3. **Arabic Typographic Tuning:** Arabic body text uses `line-height: 1.6` (compared to `1.5` in Latin) to accommodate script ascenders and descenders.

## 10. Accessibility Checklist (WCAG 2.2 AA)

- [x] **Color Contrast:** Body text achieves ≥ 4.5:1; UI controls and large headings achieve ≥ 3:1.
- [x] **Touch Targets:** All interactive buttons and chips have a minimum hit area of 44x44px.
- [x] **Visible Focus:** `:focus-visible` ring with `2px solid var(--tenant-primary)` and `2px offset`.
- [x] **Keyboard Navigation:** Full tab order navigation; Escape key dismisses modals and bottom sheets.
- [x] **Screen Reader Semantics:** Semantic heading hierarchy (`h1` -> `h2` -> `h3`), descriptive image alt attributes, and `aria-live` announcements for search results.
- [x] **Reduced Motion:** Respects `prefers-reduced-motion: reduce`, disabling non-essential animations.

---

## 11. SEO & Performance First Constraints

1. **Semantic Server HTML:**
   - Raw HTTP response for `/r/:slug` includes restaurant name in `<h1>`, category sections in `<h2>`, dish names in `<h3>`, and prices in text.
   - Content is fully visible and readable without JavaScript execution.
2. **Zero CLS Image Budget:**
   - All food and logo image containers enforce strict CSS `aspect-ratio` (`1:1` or `4:3`).
   - Skeletons mirror exact card pixel heights (`96px`).
3. **Above-the-Fold Priority:**
   - Logo uses `NgOptimizedImage` with `priority` attribute.
   - Lower dish images lazy-load with `loading="lazy"`.
4. **Target Core Web Vitals:**
   - LCP ≤ 2.5s (Mobile p75)
   - INP ≤ 200ms (Mobile p75)
   - CLS ≤ 0.1 (Mobile p75)
